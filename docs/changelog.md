# Changelog

> Part of the docs set. Source of truth: [architecture.md](./architecture.md).

Human-readable, newest-first narrative of the architecture history. Each line is a plain-English summary; the authoritative detail (with verifier notes) lives in the matching row of [verification-log.md](./verification-log.md).

- **2026-07-11 (Phase 1 live-verified; REC-7 closed)** — The merchant created a **separate dev app** (`shopify.app.delivery-scheduler-dev.toml`, own client_id, installed on `flowercart-dev`) so `npm run dev` can finally serve the working tree inside the admin, then re-ran the full Phase 1 smoke checklist against it: **all tests passed**. The URL-driven `OrderDetailsPanel` works as designed — `?order=` appears in the admin address bar and the panel survives a browser refresh — closing **REC-7 as verified** and confirming the earlier two "failures" were stale-deployed-build artifacts. Phase 1 is DONE and live-verified; next up is **Phase 2** (IndexFilters + IndexTable rewrite). → [full entry](./verification-log.md)

- **2026-07-11 (REC-7 true root cause)** — Live browser investigation proved the REC-7 "failure" was **not a code bug**: both smoke tests ran against the **old deployed Cloud Run build** — `automatically_update_urls_on_dev = false` + the same app installed on both stores means the admin always serves the registered production URL, even with `npm run dev` running and even via the dev-console preview link. The round-1 "App Bridge replace-sync" root-cause claim is withdrawn (untested premise); the push-navigation change is kept for UX. Phase 1 remains **unverified in a live admin** until it is deployed to Cloud Run or a separate dev app is created. Added a Testing-notes warning to development.md. → [full entry](./verification-log.md)

- **2026-07-11 (smoke test + REC-7 fix + Prisma pin)** — Phase 1 manual smoke test: everything passed **except** the `?order=` deep link — the admin URL never updated because App Bridge was not mirroring **replace**-based history updates to the address bar. Fixed by switching the panel open/close to **push** navigations (bonus: browser Back now closes the panel); live re-verification pending the next smoke test. Also repaired a broken Prisma update attempt: **Prisma 7 is not yet compatible** (`@shopify/shopify-app-session-storage-prisma` 9.0.1 still requires `^6.19.0`), so the project is pinned to `prisma`/`@prisma/client` **6.19.3**, with the CLI kept in `dependencies` because Cloud Run's `docker-start` runs `prisma migrate deploy` at runtime. → [full entry](./verification-log.md)

- **2026-07-11 (Phase 1 shipped)** — Orders Ops V2 Phase 1: replaced the `/app/orders` right-side `OrderDrawer` with the new **`OrderDetailsPanel`** (Polaris React, delivery-first layout: derived delivery status, reschedule timeline with from→to/source, sender phone, buy date/time, shipping fee, order history, tags). The open order is now **URL-driven** (`?order=`) — deep-linkable and refresh-safe — with a `shouldRevalidate` guard so toggling the panel doesn't re-run the loader. Loader gained two read fields (`statusPageUrl`, `$app.reschedule_status`; schema-validated, **no new scopes**). Pruned the `--p-*` token overrides from `orders-dashboard.css` (REC-10). **No write-path change** — the panel's only write is the pre-existing freeform `tagsAdd` op. typecheck/lint/tests/build all green. → [full entry](./verification-log.md)

- **2026-07-11 (design finalized)** — Locked the Orders Ops V2 **final design** after a principal-architecture review of [orders-ops-v2-ux.md](./orders-ops-v2-ux.md) + a yes/no approval round with the merchant. Key outcomes: merchant reschedule reframed as an **administrative override** (customer self-service restrictions never bind the merchant; data-integrity checks hard-enforced; slot capacity = warn + explicit confirm override); ONE shared `rescheduleOrderDelivery()` service will define the reschedule write sequence for BOTH the customer route and the merchant op — the review found the customer route inlines its mutations and leaves the legacy mirror metafields stale, which the Phase 4 refactor fixes; details panel becomes URL-driven (`?order=`); KPI cards get a "this page" scope label; audit S3 downgraded to repro-needed (Shopify eventual-consistency hypothesis) with a delayed re-poll added to the refresh spec; CSS token-override pruning moved to Phase 1; proposed hardening bundle (race guard / history re-read / staff actor / fulfilled-confirm) explicitly **declined**. Also verified the storefront cart date picker (`live-theme-clean`) has **no conflict** with V2 — it only reads `GET /apps/schedule-rules` and writes cart attributes. Docs-only, no code change. → [full entry](./verification-log.md) · [ADR-9/ADR-10](./decisions.md)
